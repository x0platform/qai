# Report Publishing — QAI Automation Framework

Documents the process for archiving test reports, publishing to GitHub Pages, and artifact retention.

## Overview

After every test execution, reports are:
1. Generated by Cucumber (HTML + JSON) and Playwright (HTML/JSON/JUnit) inside the CI container
2. Archived by `ci.yml` as the `test-reports` GitHub Actions artifact
3. Published to GitHub Pages by `pages.yml` after a successful CI run on `main`

## Report Types

| Report | Format | Output Path | Generated By |
|--------|--------|-------------|--------------|
| Cucumber HTML | HTML | `reports/cucumber-report.html` | Cucumber formatter |
| Cucumber JSON | JSON | `reports/cucumber-results.json` | Cucumber formatter |
| Playwright HTML | HTML | `reports/playwright-html/` | Playwright reporter |
| Playwright JSON | JSON | `reports/playwright-json/` | Playwright reporter |
| JUnit XML | XML | `reports/junit/` | Playwright reporter |

## CI Report Archiving

### Workflow: `.github/workflows/ci.yml`

The CI workflow archives reports as workflow artifacts:

```yaml
- name: Archive reports
  if: always()
  uses: actions/upload-artifact@v4
  with:
    name: test-reports
    path: |
      reports/cucumber-report.html
      reports/cucumber-results.json
      reports/playwright-html/**
      reports/playwright-json/**
      reports/junit/**
    if-no-files-found: warn
    retention-days: 30
```

### Downloading Artifacts

From GitHub UI:
1. Go to Actions → Select workflow run
2. Click "Artifacts" section
3. Download `test-reports` ZIP

From GitHub CLI:
```bash
gh run list
gh run download <run-id> -n test-reports
```

## GitHub Pages Publishing

### Workflow: `.github/workflows/pages.yml`

Triggered by a successful `CI` run on `main` via `workflow_run`, or manually with an optional CI run id. A push to `main` starts CI, which in turn starts this workflow.

### Steps

1. **Resolve run** — Use the triggering CI run id, the `run_id` input, or the latest successful `CI` run
2. **Download artifact** — Fetch `test-reports` with `actions/download-artifact@v4`
3. **Publish** — Replace the contents of the `gh-pages` branch with the artifact using `peaceiris/actions-gh-pages@v4`
4. **GitHub Pages serves** — Site available at `https://<org>.github.io/qai-automation/`

### Manual Publishing

```bash
gh workflow run pages.yml -f run_id=<ci-run-id>
```

Without `run_id`, the workflow selects the latest successful `CI` run.

Fallback manual copy from a downloaded artifact:

```bash
git checkout gh-pages || git checkout --orphan gh-pages
cp -r <downloaded-artifact>/. .
git add -A
git commit -m "chore: publish test reports"
git push origin gh-pages
git checkout main
```

### GitHub Pages Configuration

In repository settings:
- **Source**: Deploy from branch `gh-pages`
- **Folder**: `/ (root)`
- **URL**: `https://<org>.github.io/qai-automation/`

## Artifact Retention Policy

| Artifact | Retention | Storage | Auto-Cleanup |
|----------|-----------|---------|--------------|
| `test-reports` (Cucumber + Playwright + JUnit) | 30 days | GitHub Actions | Yes (GitHub-managed) |
| GitHub Pages site | Indefinite | `gh-pages` branch | Replaced on every publish |
| Local `reports/` directory | Session | Runner workspace | Yes (`.gitignored`) |

## Report Contents

### Playwright HTML Report Includes

- Test execution summary (passed/failed/skipped)
- Screenshots captured on failure only
- Traces retained on failure
- Video recordings retained on failure
- Browser, OS, and runtime information
- Duration per test
- Error messages and stack traces

### Cucumber JSON Includes

- Feature/scenario metadata
- Tags (`@web`, `@api`, `@smoke`, `@regression`, `@integration`, `@SxxTCxxx`)
- Step-by-step results
- Attachments (screenshots, PDFs, logs)
- Duration per step

## Automation Triggers

| Trigger | Action | Report Published |
|---------|--------|-----------------|
| Push to `dev` | CI runs, `test-reports` archived | ❌ |
| PR to `dev` | CI runs, `test-reports` archived | ❌ |
| PR `dev` → `main` | Mini-agent + CI run, `test-reports` archived | ❌ (PR only) |
| Push to `main` | CI runs, then `pages.yml` via `workflow_run` | ✅ |
| Manual `ci.yml` dispatch | CI runs, `test-reports` archived | ❌ (publish separately) |
| Manual `pages.yml` dispatch | Publishes selected/latest successful CI artifact | ✅ |

## Troubleshooting Report Publishing

### Issue: GitHub Pages not updating

**Diagnosis**:
- Check `gh-pages` branch exists
- Verify Pages source is set to `gh-pages` branch
- Check latest commit on `gh-pages`

**Resolution**:
```bash
git fetch origin
git checkout gh-pages
git pull origin gh-pages
# Verify report files exist
ls -la index.html
```

### Issue: Artifact not found

**Diagnosis**:
- Check workflow run completed successfully
- Verify artifact upload step ran
- Check retention period not expired

**Resolution**:
- Re-run CI workflow
- Download artifact within 30-day retention window

### Issue: Report HTML shows stale results

**Diagnosis**:
- `gh-pages` branch not updated after latest CI run
- Browser cache serving old version

**Resolution**:
- Re-trigger Pages publishing workflow
- Clear browser cache or use incognito mode

## Retention Cleanup (Manual)

```bash
# Delete old workflow runs (via GitHub CLI)
gh run list --limit 50 --status completed
gh run delete <run-id>

# Delete old artifacts (via GitHub CLI)
gh api repos/<org>/qai-automation/actions/artifacts
# Delete artifacts older than 30 days via API
```

## Security

- Reports may contain test data — do not include production data
- Screenshots may capture UI state — review before sharing externally
- Access to GitHub Pages is public — ensure no secrets in report content
