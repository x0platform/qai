## Repository Layout
```
apps/test-app/        # In-repo test API + Web server (Express)
packages/core/        # Shared config, API client, TestContext singleton, utils
packages/web/         # Web step definitions, page objects
packages/api/         # API step definitions, clients, payload builders
features/{web,api}/   # Gherkin .feature files
support/              # Cucumber World, hooks (screenshots, context, server lifecycle)
test-data/{pdfs,fixtures}/  # PDFs (2MB, >2MB), JSON fixtures
reports/              # Cucumber HTML + JSON outputs (gitignored)
docs/                 # STACK, RUNBOOK, traceability, report-publishing
```

## Mandatory Rules
1. Every scenario tagged: `@web|@api + @smoke|@regression|@integration + @S<scenario>TC<nnn>` (e.g. `@api @regression @S07TC001`)
2. Web tests headless by default; `HEADLESS=false` for debugging or CI headed rerun
3. Screenshots attached to the Cucumber report on failure only (`support/hooks.ts`)
4. Every `Then` step performs an explicit assertion
5. Text-validation failures include actual vs expected + diff/snippet
6. PDF tests: 2MB → expect 200 success; >2MB → expect 413 error + body message
7. Dynamic data: 3-row Examples table; cookies passed via shared `TestContext` singleton across scenarios
8. Test app started in `BeforeAll`, stopped in `AfterAll` hooks
9. No production secrets in repository; auth uses synthetic test credentials only
10. `npm run build` (tsc --noEmit), `npm run lint`, and `npm test` must pass before any commit/PR
11. Documentation coverage must remain at 100% — update docs when adding features/tests
12. Traceability matrix (`docs/traceability.md`) must be updated for every new scenario

## Report Publishing
- Cucumber HTML/JSON (`reports/cucumber-report.html`, `reports/cucumber-results.json`) are the only generated reports
- `ci.yml` archives them as the `test-reports` artifact (30-day retention)
- `pages.yml` publishes branch-scoped reports to GitHub Pages via official Pages Actions after successful CI on `dev` or `main`, or manual dispatch
- Public reports: `https://x0platform.github.io/qai/{dev,main}/` with index at `https://x0platform.github.io/qai/`
- `pr-validation.yml` mini-agent gates PRs from `dev` to `main` with file-type checks, typecheck/fix loop, lint score, and annotations
